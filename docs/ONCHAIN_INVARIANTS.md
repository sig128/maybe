# On-chain invariants

Status as of 2026-11-04, `maybe_vault` (`pUZiiWnMzroxAxPDJsjH337T5Fm9WNy92EiLNFGHgyy`) and the localnet-only `maybe_testvenue` (`4Na5xvms9PXcE7KYq97juhzznM9jsKQ5dgSJxfR4pHDJ`), Anchor 1.2.2, built with Agave 4.3.2 `cargo-build-sbf`.

Semantics live in the host-tested crate `programs/crates/maybe-logic` (plan, predicate, engine, policy, tokens, attest). Handlers in `programs/programs/maybe-vault/src/lib.rs` load accounts, check account relationships, do CPIs and persist.

## How to run the evidence

```
bash scripts/test-programs.sh
```

It runs:

1. `cargo test -p maybe-logic --release`: 4 conformance tests plus 7 unit tests.
2. `cargo test -p maybe-vault --lib`: the layout pins.
3. `anchor build`.
4. A fresh `solana-test-validator`, then `scripts/localnet-setup.ts`.
5. `npx vitest run --project sdk`: 5 unit tests plus 12 validator integration tests.

Last run: all passed. That was 12 Rust tests and 17 TypeScript tests.

The conformance fixtures in `packages/core/conformance/` are generated by `packages/core/scripts/write-conformance.ts` from the TypeScript engine. They contain:

* 16 template plans
* 20 malformed plans
* 400 predicate cases (more than 1,000 node evaluations)
* 1,296 readiness and execution cases

Rust reproduces every one of them exactly.

In the validator tests, each successful `execute_action` is predicted first by the TypeScript engine (`executeAction`). The prediction uses pool reserves read from the chain. The test then requires an exact match on four things:

* the on-chain `ExecutionReceipt`
* the strategy account
* the vault ledger
* the token balances

After every execution, the vault is reconciled with `checkVaultInvariants`.

## Invariants

| # | Invariant | Enforced in | Proven by |
|---|---|---|---|
| 1 | Only the exact signed plan executes. Upload is `create_strategy` (commits `sha256`), then `write_plan` (creator, contiguous), then `activate_strategy`, which requires `sha256(bytes) == plan_hash`. No instruction alters a plan after activation; an edit is a new strategy, which needs a new signature. | `activate_strategy`, `write_plan`, `execute_action` (`expected_plan_hash`) | localnet *account substitution* (`PlanHashMismatch`), *write by non-creator* (`Unauthorized`); conformance `plans_round_trip_and_hash` |
| 2 | Plans decode strictly and canonically, with the same first error as TypeScript. | `plan.rs` `PlanView::parse` / `check_structure` | conformance `invalid_plans_rejected_with_same_code` (20) and `plans_round_trip_and_hash` (16) |
| 3 | Predicate (t, f) semantics are identical to `predicate.ts`. This covers lazy finality, VOID = false, disputes never final, veto evaluated at `trigger.t + window`, the balance deadline +1, and receipts. | `predicate.rs` | conformance `predicate_times_match` |
| 4 | Readiness, amounts, the pro-rata fee, holdings, branch claims and run/nonce accounting are identical to `engine.ts`. | `engine.rs` | conformance `engine_readiness_and_execution_match` (1,296 cases); localnet engine-vs-chain comparisons |
| 5 | Conservation holds per mint: `token_account == available + reserved`, and `reserved == Σ holdings` of active strategies. Deposits credit the measured delta and must equal the amount. | `deposit`, `withdraw`, `activate_strategy`, `execute_action`, `close_impl` | localnet: reconciliation after every execute and close in all scenarios; core property test (`conservation under random operation sequences`) |
| 6 | Reserved funds are never withdrawable. Withdraw needs the owner signature and `amount ≤ available`. | `withdraw` | localnet `InsufficientAvailable`, `NotOwner` (stranger, agent session key) |
| 7 | Branch exclusivity: once a branch of a group executes, its siblings never can. | `engine::apply` (claim) and `readiness` (`BranchLost`) | localnet flagship (`BranchLost` on the A-NO release after A-YES executed); core property test |
| 8 | Execution is idempotent. `run` is a per-action nonce and must equal the run computed on-chain; `runs_done` advances in the same transaction. | `engine::prepare`, `engine::apply` | localnet flagship duplicate (`ActionComplete`); conformance `RUN_OUT_OF_ORDER` cases |
| 9 | A failed route never consumes an allocation. All writes happen after the CPI succeeds, and a revert discards everything. | `execute_action` ordering, transaction atomicity | localnet malicious routes: strategy, ledger and balances byte-identical after each rejection |
| 10 | Route safety. Each of these must hold: <ul><li>the route program is the configured program for the plan's route kind;</li><li>the pool is the plan's ref and is owned by that program;</li><li>the mint pair matches;</li><li>no vault-owned token account appears anywhere in the route slice;</li><li>`0 < spent_in ≤ amount_in`;</li><li>`received ≥ min_out` (the rate is recomputed on `spent_in`).</li></ul> | `exec_swap` | localnet: `overspend` → `RouteDeltaViolation`, `underdeliver` and `redirect` → `MinOutNotMet`, vault account substituted into a pool slot → `ForeignVaultAccountInRoute`; core venue tests |
| 11 | TRANSFER pays only the plan's fixed recipient. The destination token account must be owned by `plan.refs[ref]` and hold the plan's mint. | `exec_transfer` | localnet conditional payment (redirect → `TokenAccountMismatch`, then the exact amount arrives) |
| 12 | Fees are bounded: `max_fee_bps ≤ config cap ≤ 100`, action fee ≤ plan max, the fee is pro-rata to the filled amount and paid only to the asset's configured treasury, and releases carry no fee. | `plan.rs`, `engine::settle_swap`, `exec_swap` | conformance fee cases; invalid plans (`FEE_TOO_HIGH`); localnet receipts equal the engine's fee |
| 13 | Attestations require all of: <ul><li>at least the threshold of distinct, non-revoked keys of the bound set;</li><li>Ed25519 precompile offsets that point into the same instruction;</li><li>a domain-separated message covering program, event, rule hash, outcome, observed_at, nonce and expiry;</li><li>a strictly increasing nonce;</li><li>an expiry not yet passed.</li></ul> A conflicting outcome during the window sets DISPUTED. Adjudication needs a super-threshold. An unadjudicated dispute times out to VOID. | `attest`, `adjudicate`, `void_disputed`, `attest.rs` | localnet attestation test: 1 signer, duplicate signer, stranger, wrong domain → `AttestationInvalid`; expired → `AttestationExpired`; replay → `AttestationReplay`; dispute then 2-of-3 adjudication refused, 3-of-3 → FINAL. Unit tests for offset and duplicate handling |
| 14 | Development attestors work only while `allow_dev_attestors = 1`. `disable_dev_attestors` is one-way. | `init_attestor_set`, `attest`, `adjudicate`, `disable_dev_attestors` | localnet last test (`DevAttestorForbidden` for both attest and new dev sets) |
| 15 | The objective balance event is bound in its PDA seeds to the watched token account. YES requires an observation with `now ≤ deadline` and balance ≥ threshold; NO is final at `deadline + 1`. | `observe_balance`, `effective()` | localnet balance-threshold test; conformance BALANCE cases |
| 16 | Listed assets are classic SPL Token, or Token-2022 with only MetadataPointer, TokenMetadata and Group extensions. | 17 | Each vault holds exactly one canonical token account per mint, `ATA(vault, mint, program)`, and every deposit, withdraw and execute checks it. | `register_mint`, `deposit`, `withdraw`, `exec_context` | localnet deposit to a non-vault account → `TokenAccountMismatch` |
| 18 | Agent session keys can only create plans inside the policy: allowed mints, routes and recipients; per-step cap; total cap; fee cap; expiry; current epoch. They can never withdraw. The kill switch bumps the epoch. | `create_strategy`, `activate_strategy`, `policy.rs` | localnet agent test (in-policy succeeds and `spent` is charged; too large / other route → `PolicyViolation`; withdraw → `NotOwner`; after kill switch → `PolicyRevoked`); unit `policy_bounds_agent_plans` |
| 19 | The emergency pause blocks `execute_action` only. Withdraw, cancel, expiry close and refunds keep working. | `set_paused`, `readiness` (`ExecutionPaused`) | localnet pause test |
| 20 | The admin can never move vault funds. No instruction transfers from a vault token account except: <ul><li>`withdraw` (owner);</li><li>`execute_action` (constrained by the plan);</li><li>fees capped by the plan's `fee_bps`.</li></ul> If the admin later changes a route program, the plan's pool is not owned by it, so executions fail closed. Delisting an asset blocks deposits and activations but never withdrawals or executions of existing plans. | design; `exec_swap` ownership checks | code review; localnet route-ownership checks |

Zero-copy account layouts (`Config` 1,896 B, `Vault` 696 B, `Strategy` 3,592 B, `Policy` 776 B) are pinned by `state.rs::layout_tests` and decoded at those offsets by `packages/sdk/src/accounts.ts`. IDL-derived discriminators are cross-checked in `packages/sdk/test/unit.test.ts`.

## Remaining-account layouts (as implemented)

* `activate_strategy`: every plan event in order, then every plan ref in order.
* `execute_action`: plan events in order, then receipt-referenced strategies in ascending ref index, then:
  * CP_SWAP: `[route_program, pool, mint_a, mint_b, pool_vault_a(w), pool_vault_b(w), token_program_a, token_program_b, vault_src(w), vault_dst(w), treasury(w)]`
  * OUTCOME_BUY: `[route_program, market, collateral_mint, yes_mint(w), market_vault(w), token_program, vault_src(w), vault_dst(w), treasury(w)]`
  * OUTCOME_REDEEM: `[route_program, market, event, collateral_mint, yes_mint(w), market_vault(w), token_program, vault_src(w), vault_dst(w), treasury(w)]`
  * TRANSFER: `[vault_src(w), mint, recipient_token_account(w), token_program, treasury(w)]`
  * RELEASE: none
* `close_completed`: plan events, then receipt-referenced strategies.

`MaybeClient.executeAccounts` (in `packages/sdk/src/client.ts`) builds these lists.

## Not implemented, or only tested off-chain

* **Jupiter, PumpSwap and Pump bonding-curve route adapters: externally blocked.** This environment cannot reach mainnet RPC or the programs. They cannot be cloned into the local validator, and Jupiter's swap API is unreachable. On-chain swaps exist only for the local test venue route kinds (CP_SWAP, OUTCOME_BUY, OUTCOME_REDEEM). A production adapter would need its own route kind and account-slice rules. The balance-delta, ownership and vault-account checks above apply unchanged.
* **Real prediction-venue positions (Polymarket, Kalshi/DFlow) are not held by vaults.** Research shows eligibility and KYC requirements, and no PDA-compatible trading. Those venues can only be read and then attested. No production attestor set or signer exists. The dev set is labeled `is_dev` and can be disabled for good.
* **Time-dependent paths are proven on the host only.** Schedules (skip / catch-up), delays, vetoes and action deadlines are covered by the engine conformance fixtures and Rust tests, not by a validator run. Exercising them live would need clock warps.
* **Cross-strategy receipts are not exercised on the validator.** Dependent-strategy receipts (an external `RECEIPT` ref) and `close_completed` with external receipts are implemented and conformance-tested for the self-receipt case only.
* `init_config` is first-caller-wins. It has no upgrade-authority check, so deployments must call it right after deploy. No upgrade-authority or multisig policy is configured.
* Closed strategy accounts are not reclaimed: there is no instruction to recover their rent.
* The policy `can_cancel` flag is stored but unused. Only the owner cancels.
* The Ed25519 scan reads at most 32 instructions per transaction.
* TRANSFER accepts any token account owned by the recipient, not only its ATA.
* `create_event` is permissionless. An event's identity (adapter, market-id hash, rule hash, binding) lives in its PDA seeds, and plans pin exact event addresses, so impostor events cannot affect existing plans.
* Compute observed on localnet: around 20–60k CU per execute, against a client limit of 600k. These are not formal benchmarks.
